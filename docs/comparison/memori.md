# Dynamiq vs Memori (LangChain Memory)

## Pitch

"Memori" here refers to [LangChain's memory
module](https://python.langchain.com/docs/modules/memory/) — the
in-process memory primitives that LangChain agents use (chat history
buffers, summary memory, vector store memory, entity memory, etc.).
There's a separate project named [Memori by
GibsonAI](https://github.com/GibsonAI/memori) that does
"conscious-ingest" — promotion from short-term to long-term memory
after repeated retrieval — which we cover at the end.

## Data model (LangChain Memory)

LangChain Memory classes wrap a backing store (Redis, Postgres,
SQLite, in-memory) with one of:

- `ConversationBufferMemory` — append-only chat history.
- `ConversationSummaryMemory` — LLM-summarised history.
- `VectorStoreRetrieverMemory` — embed messages, retrieve relevant.
- `ConversationEntityMemory` — extract entities mentioned, track
  facts per entity.

Each is a thin Python class; there's no formal graph model, no
ontology, no provenance layer.

Dynamiq stores a typed bi-temporal property graph in Postgres with
PROV-O on every fact.

| | Dynamiq | LangChain Memory |
|---|---|---|
| Bi-temporal edges | ✅ | – |
| Typed ontology | ✅ | – |
| W3C PROV-O | ✅ | – |
| Multi-tenant workspaces | ✅ | application's job |
| MCP server | ✅ | – |
| Built-in chunking | – | partial |

## Standards

LangChain Memory has no semantic-web layer — no JSON-LD, no PROV-O,
no SKOS. Dynamiq emits all of those at the API boundary.

## Permissioning

LangChain Memory has no built-in scoping beyond what the backing
store provides. Dynamiq enforces workspace RLS at Postgres and layers
sensitivity-label policies on top.

## Provenance

LangChain Memory tracks "this message came from this conversation".
Dynamiq tracks "this fact was generated by activity X, run by agent
Y of kind Z, derived from upstream activities A and B".

## Agent surface

LangChain Memory is invoked from inside a LangChain agent loop;
there's no network surface unless you build one. Dynamiq exposes an
MCP server reachable from any client.

## Memori by GibsonAI

The other project under the same name. "Conscious-ingest" is a
neat idea: keep recently-promoted-from-retrieval items in a short-term
buffer that auto-merges into long-term storage after N retrievals.
Dynamiq's roadmap has it under "Phase Z+" — promote-on-retrieval over
edges that have been read N times. Not shipped today.

## When to pick which

**Pick LangChain Memory if** you're already in the LangChain
ecosystem, your agent is single-tenant, and you don't need a typed
graph or formal provenance.

**Pick GibsonAI Memori if** you want short-term → long-term promotion
mechanics specifically.

**Pick Dynamiq if** you need a real knowledge graph with audit-grade
provenance and a multi-tenant production story.
